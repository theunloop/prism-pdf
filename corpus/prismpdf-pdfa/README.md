Prism PDF PDF/A corpus
====================

A **Prism PDF-authored** PDF/A conformance corpus, graded by the veraPDF oracle — the
self-validating counterpart to the third-party suites under `corpus/external/`
(Isartor / BFO / veraPDF). Unlike those (negative tests, not committed for licensing
reasons), every file here is generated by *us*, so it is redistributable and **committed**.

Why a second corpus when `corpus/external/` already exists? The external suites test a
*validator* with files someone else crafted. This corpus is **PASS-only**: it proves our
*producer*. `make_pdfa`/`make_pdfua`/`make_pdfua2` (ISO 19005 parts **1–4** — all eleven
flavours 1a/1b, 2a/2b/2u, 3a/3b/3u, 4/4e/4f — plus PDF/UA-1/-2) emits a file for **every
feature×flavour the library can author**, and veraPDF confirms each is `isCompliant`. A
non-compliant verdict is a producer bug. (There is deliberately **no FAIL corpus** — broken
files test a *validator*, which Prism PDF does not have; that is out of scope here.)

The authoritative list of *what* could be tested is [`checklist.md`](checklist.md): all **156**
rules veraPDF 1.30.2 enforces across the part-2/3 flavours, extracted from its validation
profiles (ISO 19005 itself is not in `docs/rfc/`, so the profiles — the same checks the oracle
applies — are the source of truth). Of those, **111 are actively proven** by emitting the object
they govern; the remaining **45 (`VAC`)** govern objects the producer does not author yet (text
form fields, optional content, …). The part-1 profiles (`PDFA-1A/1B`, **135** distinct rules)
and part-4 profiles (`PDFA-4/4E/4F`, **111** distinct rules) are enforced the same way on the
`1a`/`1b`/`4`/`4e`/`4f` files, at flavour granularity (no per-rule table yet).
[`coverage-gaps.md`](coverage-gaps.md) explains each `VAC` area and maps it to `spec-map.md`.

Naming convention
-----------------

The data-driven harness (`crates/pdf/tests/conformance_corpus.rs`) discovers files by filename:

```
prismpdf-<feature>-<flavour>-pass.pdf
|        |         |        |
|        |         |        +-- expectation: a conformant validator must ACCEPT it
|        |         +-- flavour: 1a | 1b | 2a | 2b | 2u | 3a | 3b | 3u | 4 | 4e | 4f | ua1 | ua2  (also the grouping key)
|        +-- what the file exercises: blank | vector | image | imagegray | imagejpeg |
|            imagealpha | imagestencil | figure | signed | link | note | form |
|            text | tagged | attach | accessible
+-- this corpus
   e.g.  prismpdf-text-2u-pass.pdf      (PDF/A-2U, embedded-font text)
```

Files are keyed by flavour (a conformant file satisfies *many* clauses at once, so a single
clause key would be misleading) — analogous to how the harness keys veraPDF's TWG files by
profile rather than clause.

Generation
----------

Files are produced through the normal authoring API and finalised with `make_pdfa`/`make_pdfua`
(see `crates/pdf/examples/gen_pdfa.rs`). Regenerate with:

```text
cargo run -p prismpdf --example gen_pdfa -- corpus/prismpdf-pdfa
```

The embedded-font samples (`text`, `tagged`, `accessible`) need a TrueType font; pass its path
or set `PRISMPDF_FONT` (CI installs `fonts-dejavu-core`). `PRISMPDF_CMYK_PROBE=1` additionally
writes a deliberately non-conformant DeviceCMYK file (`cmyk-probe.pdf`) to demonstrate the
CMYK-OutputIntent gap — for inspection only, never committed.

Grading
-------

These files are walked by the same harness and graded against the **veraPDF oracle**
(`isCompliant`) when the CLI is on `PATH`, else against the `-pass` filename label.
This corpus is committed, so the harness walks it **by default** (alongside `corpus/external/`
when that's present) — no env var needed:

```text
cargo test -p prismpdf --test conformance_corpus conformance_corpus -- --exact --nocapture
```

To grade *only* this corpus, point the override at it with an absolute path
(`PRISMPDF_CONFORMANCE_CORPUS="$PWD/corpus/prismpdf-pdfa"`); set it to any other path to walk a
specific suite instead.

The report (grouped by corpus → flavour) lands in `target/conformance-report.json`; the
baseline and how to read the numbers live in `docs/baselines/conformance.md`. A file the oracle
calls non-compliant is a real **producer** bug.

Manifest: [`description.txt`](description.txt) — one entry per file with its flavour and the ISO
clauses it exercises. Gaps: [`coverage-gaps.md`](coverage-gaps.md).
