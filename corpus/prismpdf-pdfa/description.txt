Prism PDF PDF/A corpus — per-file manifest
========================================

One entry per file: the PDF/A flavour and the ISO 19005 clauses it is meant to exercise. This
corpus is PASS-only — every file is conformant output from the producer, so a non-compliant
veraPDF verdict is a producer bug. The authoritative rule list is checklist.md; the gaps that
keep some rules untested are in coverage-gaps.md.

Filename convention (see README.md):
  prismpdf-<feature>-<flavour>-pass.pdf      <- conformant output proving the producer (make_pdfa)


PASS corpus — generated by `cargo run -p pdf --example gen_pdfa -- corpus/prismpdf-pdfa`
--------------------------------------------------------------------------------------
78 files: every (feature, flavour) make_pdfa / make_pdfua / make_pdfua2 can produce, so every producer
accept-path is validated. Each must validate as isCompliant under the flavour veraPDF
auto-detects from its XMP. Every file also carries the A-base structural rules (header 6.1.2,
trailer/ID 6.1.3 + 14.4, xref 6.1.4, XMP identification 6.7/pdfaid, sRGB OutputIntent
6.2.2/14.11.5).

Untagged content is valid at the B and U levels (and at plain part 4, which has no levels), but
never at level A (which requires tagging); tagged documents are valid at every level;
attachments require part 3 or the part-4 F/E extensions. Part 1 (PDF 1.4) additionally forbids
image transparency, so the imagealpha feature starts at part 2; part 4 (PDF 2.0) forbids an
/Info dictionary, so its files keep all metadata in the XMP alone.

  prismpdf-blank-{1b,2b,2u,3b,4}-pass.pdf  feature: blank
      Minimal conformant document: a single blank page. No fonts, no graphics — proves the
      structural baseline alone (the -1b file also proves the %PDF-1.4 pin + classic xref;
      the -4 file the %PDF-2.0 pin, pdfaid:rev and the absent /Info).

  prismpdf-vector-{1b,2b,2u,3b,4}-pass.pdf feature: vector
      DeviceRGB vector fill + stroke. Proves uncalibrated device colour is admissible
      *because* an OutputIntent is present (6.2.4.*); content-stream operators (6.2.2).

  prismpdf-image-{1b,2b,2u,3b,4}-pass.pdf  feature: image (raster, DeviceRGB)
      A raw RGB raster image embedded as an image XObject (FlateDecode). Proves image
      authoring (6.2.8 image XObject, 6.2.9 XObject use).

  prismpdf-imagegray-{1b,2b,2u,3b,4}-pass.pdf  feature: imagegray (DeviceGray)
      A DeviceGray raster image. Proves device-gray colour is admissible with the OutputIntent
      present (6.2.4.3) and the gray image path.

  prismpdf-imagejpeg-{1b,2b,2u,3b,4}-pass.pdf  feature: imagejpeg (DCTDecode)
      A JPEG embedded as-is via DCTDecode (7.4.8) — the photographic case. Proves the DCT
      image filter under PDF/A.

  prismpdf-figure-{1a,2a,3a}-pass.pdf      feature: figure (tagged image, level A)
      A raster image carried by a Figure structure element with /Alt text — an accessible
      image (6.8 logical structure + 6.2.8 image, at level A).

  prismpdf-text-{1b,2b,2u,3b,3u,4}-pass.pdf  feature: text (embedded font)
      A paragraph in an embedded TrueType font with Unicode text. Proves font embedding
      (6.2.11.*), CIDToGID/glyph presence (6.2.11.4/.5), and ToUnicode coverage (required at
      the U level — the -2u and -3u files are the meaningful U tests).

  prismpdf-tagged-{1b,1a,2b,2u,2a,3b,3a,4}-pass.pdf  feature: tagged (embedded font + structure tree)
      A tagged document (heading + paragraph + list) with a logical structure tree. The -1a,
      -2a and -3a files are the level-A tests (6.8 logical structure, /MarkInfo,
      /StructTreeRoot, document language); the B/U (and part-4) variants prove the tree
      survives at those levels too.

  prismpdf-signed-{1b,2b,2u,3b,4}-pass.pdf feature: signed (digital signature)
      A conformant base document then signed via Document::sign (detached CMS, RSA-SHA256) as an
      incremental update. Proves digital signatures under PDF/A (6.4.3: signature dict +
      PKCS#7/CMS). The signature is *invisible* on purpose — a visible appearance would draw with
      non-embedded Helvetica, which PDF/A forbids. Signed with a committed throwaway test key and a
      fixed signing time, so the file is byte-reproducible. The invisible widget still carries
      an (empty) /AP appearance — ISO 19005-1 6.9 requires one on every form field.

  prismpdf-attach-{3b,3u,4f,4e}-pass.pdf   feature: attach (parts 3 and 4F/4E only)
      A document with an embedded XML file associated at the catalog (the e-invoicing case).
      Proves associated files (6.8 / 14.13: /AF, /EmbeddedFiles, /AFRelationship) — permitted
      only from part 3 and by the part-4 F/E extensions (ISO 19005-4 Annex A/B). Untagged; the
      page carries no text, so it is valid at both level B and level U.

  prismpdf-blank-3u-pass.pdf               feature: blank (PDF/A-3U, level U)
      The minimal part-3 / level-U document — a blank page. Level U requires all text to be
      Unicode-mapped; with no text it is trivially U-conformant. The text-3u file carries the
      real Unicode-text proof (embedded font + ToUnicode at part 3, level U).

  prismpdf-link-{1b,2b,2u,3b,4}-pass.pdf   feature: link (annotations, M16)
      Hyperlink annotations: an external URI action and an internal GoTo — no appearance
      stream needed (6.3.3 exemption for Link), permitted actions only (6.5.1), Print flag
      set / Hidden clear (6.3.2). Links carry /Contents alternate descriptions.

  prismpdf-note-{1b,2b,2u,3b,4}-pass.pdf   feature: note (Text annotation, M16)
      A Text note annotation with /Contents and a generated normal appearance stream — the
      6.3.3 requirement for non-link subtypes, drawn as a Form XObject (6.2.9-clean).

  prismpdf-imagealpha-{2b,2u,3b,4}-pass.pdf  feature: imagealpha (soft mask, M16)
      An RGBA raster split into base image + /SMask alpha soft mask (6.2.8 transparency via
      SMask is admissible from part 2 on; PDF/A-1 forbids it — make_pdfa rejects it there
      with TransparencyRequiresPdfA2, so there is deliberately no -1b file).

  prismpdf-imagestencil-{1b,2b,2u,3b,4}-pass.pdf  feature: imagestencil (stencil mask, M16)
      A 1-bit /ImageMask stencil applied via /Mask — the other §8.9.6.3 masking form
      (PDF/A 6.2.8 t5). A stencil is not transparency, so it is valid at part 1 too.

  prismpdf-form-{1b,2b,2u,3b,4}-pass.pdf   feature: form (AcroForm checkbox, M16)
      An interactive checkbox with a vector /On+/Off appearance subdictionary: no
      /NeedAppearances, no /XFA, no widget actions (6.4.1/6.4.2), state-keyed /AP /N
      (6.3.3 t3). Widgets carry /TU and /Contents descriptions.

  prismpdf-accessible-ua1-pass.pdf         feature: accessible (PDF/UA-1)
      Adjacent standard (ISO 14289-1, not 19005): a tagged, accessible document declaring
      PDF/UA-1 with /DisplayDocTitle and document language. Included here because it shares
      the tagged-PDF machinery; validated via make_pdfua. M22 UA-1 surface: numbered list
      (/ListNumbering), captioned figure (Caption), Note with /ID (+/IDTree), checkbox
      widget nested in Form via /OBJR (with /TU + /Contents), /Tabs /S.

  prismpdf-accessible-ua2-pass.pdf         feature: accessible (PDF/UA-2, PDF 2.0)
      Adjacent standard (ISO 14289-2:2024 on ISO 32000-2): root Document element in the
      PDF 2.0 structure namespace, XMP pdfuaid:part 2 + pdfuaid:rev, Title element,
      FENote bidirectionally /Ref-linked with its citing paragraph, an intra-document link

      and a custom Callout type in its own namespace role-mapped to Aside via /RoleMapNS,
      plus the UA-1 surface above; validated via make_pdfua2 with veraPDF --flavour ua2
      (1727 rules / 2250 checks, 0 failed).


Not produced (see coverage-gaps.md)
-----------------------------------
The 60 `VAC` rules in checklist.md govern objects the producer does not author: annotations,
forms, actions, optional content, transparency/blend, halftones, Separation/ICC colour, form
XObjects, inline images, image masks, JPEG2000, PDF/A extension schemas, and the signature
DocMDP/permissions variants (the basic signature itself is now covered by `signed`). Most are
read-only in Prism PDF (authoring deferred) or out-of-scope v1; one is blocked (DeviceCMYK needs a
CMYK OutputIntent — make_pdfa ships sRGB only). coverage-gaps.md maps each to spec-map.
